## 1. Математический базис

### 1.1. Симплициально-клеточный комплекс данных ($X$)
В отличие от реляционных таблиц Кодда и графов свойств (Property Graphs), TopoSpatiaDB структурирует данные как ориентированный симплициальный клеточный комплекс произвольной размерности $n$:
$$X = \bigcup_{k=0}^n X^{(k)}$$
- **0-симплексы (Вершины $X^{(0)}$)**: Узлы данных, физические реплики кластера или шарды.
- **1-симплексы (Ребра $X^{(1)}$)**: Каналы связи, бинарные реляционные связи и конвейеры репликации.
- **2-симплексы (Грани $X^{(2)}$)**: Треугольники кворумов и замкнутые транзакционные циклы.
- **$k$-симплексы ($X^{(k)}$)**: Гиперсимплексы, координирующие многосторонние транзакции и инварианты целостности.

### 1.2. Клеточные пучки и векторные стебли ($\mathcal{F}$)
Каждому симплексу $\sigma \in X^{(k)}$ сопоставляется локальное гильбертово пространство состояний — **стебель пучка** $\mathcal{F}(\sigma) \cong \mathbb{R}^{d_\sigma}$.
Между инцидентными клетками $\sigma \trianglelefteq \tau$ действуют линейные операторы рестрикции:
$$\rho_{\sigma \trianglelefteq \tau} \colon \mathcal{F}(\sigma) \longrightarrow \mathcal{F}(\tau)$$

### 1.3. Кограничные операторы Чеха–Де Рама и когомологии
Градуированное пространство $k$-коцепей:
$$C^k(X, \mathcal{F}) = \bigoplus_{\sigma \in X^{(k)}} \mathcal{F}(\sigma)$$
Кограничный оператор $d_k \colon C^k \to C^{k+1}$:
$$(d_k x)(\tau) = \sum_{\sigma \trianglelefteq \tau} [\tau : \sigma] \, \rho_{\sigma \trianglelefteq \tau}(x(\sigma))$$
**Теорема нильпотентности**:
$$d_{k+1} \circ d_k = 0 \quad \forall k \ge 0$$
Позволяет построить группы высших когомологий $H^k(X, \mathcal{F}) = \ker(d_k) / \operatorname{im}(d_{k-1})$.

### 1.4. Высший Лапласиан Ходжа и бесконфликтный консенсус
Оператор Лапласа—Бельтрами $\Delta_k \colon C^k \to C^k$ раскладывается на две неотрицательные компоненты:
$$\Delta_k = \Delta_k^{\mathrm{down}} + \Delta_k^{\mathrm{up}} = d_{k-1} d_{k-1}^* + d_k^* d_k$$
- **Разложение Ходжа**: $C^k(X, \mathcal{F}) = \ker(\Delta_k) \oplus \operatorname{im}(d_{k-1}) \oplus \operatorname{im}(d_k^*)$
- **Изоморфизм Ходжа**: $\ker(\Delta_k) \cong H^k(X, \mathcal{F})$

**Физический смысл в СУБД**:
- Расхождения реплик и конфликты одновременной записи — это вихри $H^1$.
- Энергия расхождения вычисляется через функционал Дирихле:
  $$E(x) = \langle x, \Delta_0 x \rangle$$
- Для устранения конфликтов TopoSpatiaDB запускает непрерывный градиентный поток:
  $$\frac{dx}{dt} = -\Delta_0 x \implies x(t) = \exp(-t \Delta_0) x(0)$$
  При $t \to \infty$ состояние гарантированно проецируется на гармоническое ядро $\ker(\Delta_0)$ с $E(x) \to 0$ без блокировок и дедлоков!

## 2. Архитектура движка и многопоточность

Система построена на модульном разделении ответственности:

```
+--------------------------------------------------------------------------+
|                        HTTP REST & Dashboard (server.go)                 |
|   /api/v1/simplex  |  /api/v1/records  |  /api/v1/consensus/diffuse      |
+--------------------------------------------------------------------------+
                                     |
               +---------------------+---------------------+
               |                                           |
               v                                           v
+-------------------------------+         +--------------------------------+
|  Topological Sheaf Core       |         |  ACID WAL Storage Engine       |
|  (sheaf.go)                   |         |  (storage.go)                  |
|  - RWMutex: Read/Write Split  |         |  - Append-only WAL (JSON Lines)|
|  - d_k Coboundary matrices    |         |  - RWMutex Snapshot Isolation  |
|  - Delta_k Hodge Laplacians   |         |  - SHA-256 State Signatures    |
|  - Lock-free Vector Math      |         |  - Atomic TxID monotonic clock |
+-------------------------------+         +--------------------------------+
               ^                                           ^
               |                                           |
               +---------------------+---------------------+
                                     |
+--------------------------------------------------------------------------+
|                     Consensus Engine (consensus.go)                      |
|   - Continuous Heat Kernel Flow: x_{t+1} = x_t - dt * Delta_0 * x_t      |
|   - Zero-overhead Dirichlet Energy convergence check                     |
+--------------------------------------------------------------------------+
```

### Модели конкурентности и синхронизации:
1. **Многопоточное чтение (Scalable Shared Read Locks)**:
   - Операции `Get` и топологические срезы используют `sync.RWMutex.RLock()`.
   - Возврат срезов векторов защищен глубоким копированием (`CloneVector`), что исключает гонки данных при параллельной диффузии.
2. **Сериализация изменений (WAL Serialization)**:
   - Операции мутации `Put` атомарно инкрементируют счетчик транзакций и записывают запись в WAL перед обновлением индексов в ОЗУ.
3. **Параллельная диффузия Ходжа**:
   - Матрица $\Delta_0$ компилируется один раз при изменении структуры комплекса и кэшируется, позволяя параллельным воркерам вычислять диффузионные шаги с нулевыми блокировками.

### 3.2. Архитектурный прорыв оптимизации:
1. **Ликвидация отрицательного масштабирования OLTP**:
   - Ранее при 8 потоках в тесте 80R/20W производительность деградировала (с 22.1K до 20.7K TPS).
   - После разбиения индекса на **32 независимых шардовых мьютекса (Striped Locks)** и выноса вычисления SHA-256 за критические секции, пропускная способность выросла с 4 920 TPS на 1 потоке до **46 340 TPS на 8 потоках** (ускорение в **9.42x**!).
2. **Параллельная запись (Group Commit Scalability)**:
   - Ранее переход с 1 на 8 ядер давал лишь +14.5% прироста из-за сериализации на глобальном мьютексе файла.
   - С конвейером **WAL Group Commit** (батчинг до 256 транзакций / 200 мкс) пропускная способность при конкурентной записи выросла с 988 TPS до **9 370 TPS** (рост в **9.48x**!).
3. **Чтение и Диффузия**:
   - Чтение: **7.48 млн QPS** (эффективная обратная задержка 133.6 нс).
   - Диффузия Ходжа: **2.59 млн шагов/сек** на 4 физических ядрах (ускорение 3.34x благодаря Zero-Allocation матричной арифметике).
